# Storage and Permissions

---

## Local Disk Setup

File Converter uses the `local` filesystem disk for both uploaded source files and conversion results. Files are stored under `storage/app/`:

```
storage/app/uploads/{user_id}/          — uploaded source files
storage/app/conversions/results/{job_id}/  — conversion result files
```

Neither directory is publicly accessible. Downloads are served through the application via signed controller routes.

---

## Storage Symlink

If you use any public assets (not required for file storage in MVP), create the symlink:

```bash
php artisan storage:link
```

---

## Writable Directories

The web server user must have write access to:

```bash
chmod -R ug+rwx storage bootstrap/cache
```

**Do not use `chmod -R 777`** — this is a security risk on shared servers.

---

## Upload Size Limits

PHP controls maximum upload size. Set in `php.ini` or a `.user.ini` file:

```ini
upload_max_filesize = 50M
post_max_size = 55M
```

Web server limits also apply:

**Nginx:**
```nginx
client_max_body_size 55M;
```

**Apache:**
```apache
LimitRequestBody 57671680
```

---

## File Retention

Files expire based on the plan's retention policy:

- Free plan: default retention (configured via `CONVERTER_DEFAULT_RETENTION_DAYS`)
- Pro/Max plan: extended retention

After expiration, the cleanup command deletes the physical files and marks the records expired. Configure the retention period in `.env`:

```env
CONVERTER_DEFAULT_RETENTION_DAYS=1
```

---

## Production Warning

Source files and result files contain user-uploaded content. Ensure:

- `storage/app/` is **not** publicly accessible
- No web server alias points directly to `storage/app/`
- The `storage:link` symlink only links `storage/app/public/` (not used in MVP)

---

## Backup Notes

If you back up the application:

- Include the `storage/app/uploads/` and `storage/app/conversions/` directories
- Or accept that expired/deleted files are not critical to restore (results can be regenerated by re-converting)
